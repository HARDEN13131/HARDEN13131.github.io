争取暑假拿下第一个EDUsrc漏洞

🎓 edu SRC 漏洞挖掘入门指南

适用人群：有 CTF 基础、第一次玩 SRC、主攻 Web 与小程序的师傅
目标：2-4 周内出第一单，建立可复用的工作流

一、为什么选 edu SRC 起步

优势 说明
门槛低 教育行业安全水位普遍偏低，弱口令、默认配置、信息泄露一挖一个准
收录快 edu 类 SRC 普遍出报告 1-3 天审核
资产广 一个高校 = 几十个站点（教务、OA、图书馆、邮件、一卡通、研究生系统…）
经验友好 即使无现金奖励，积分和证书能快速攒 SRC 履历
合规 都在授权范围内，不踩红线

典型收录漏洞类型（按出单率高到低排）：

  1. 弱口令 / 默认口令 / 万能密码
  2. 信息泄露（学号、身份证、成绩、源码、备份文件）
  3. 未授权访问 / 越权（水平/垂直）
  4. SQL 注入
  5. SSRF
  6. XSS（存储型为主，反射型通常不收）
  7. 逻辑漏洞（支付、签到、抽奖、找回密码）
  8. 文件上传 / 解析漏洞
  9. 小程序鉴权绕过

二、整体工作流（建议严格按顺序）

核心原则：先广后深，先信息泄露再深逻辑。edu 站 80% 的单子出在第 3 步。

三、目标选择策略

推荐的入手顺序

  1. 985/211 头部高校 — SRC 体系成熟，回复快，奖励明确
    • 清华、北大、复旦、上交、浙大（多数有自己的 SRC）
  2. 省属重点本科 — 资产多、外包多，漏洞密度高
  3. 高职/专科 — 漏洞极多但部分 SRC 不收录，慎选
  4. 教育平台类 — 慕课平台、智慧树、学习通、职教云

找 SRC 入口的方法

  • Google: site:xxx.edu.cn 安全应急响应 或 xxx SRC
  • 看目标高校官网底部 → “安全公告” / “漏洞报送”
  • 国内聚合：补天、漏洞盒子有 edu 专项

⚠️ 没有 SRC 的高校不代表不能挖，但要先确认有公开授权（页面声明、邮箱等），避免法律风险。

四、资产收集（这是最关键的一步）

4.1 子域名 / 资产发现

工具 用途 命令示例
OneForAll 子域爆破 python3 oneforall.py --target xxx.edu.cn run
subfinder 快速子域 subfinder -d xxx.edu.cn -o subs.txt
fofa / hunter / quake 资产测绘 domain="xxx.edu.cn" && protocol="http"
Google Dorks 手工挖掘 site:xxx.edu.cn inurl:admin、inurl:login
dnsdumpster / crt.sh 证书透明度 网页搜索目标域名

重点关注的子域：

  • jwc.xxx.edu.cn — 教务系统（高频出单点）
  • oa.xxx.edu.cn / mail.xxx.edu.cn — OA / 邮件
  • library.xxx.edu.cn — 图书馆
  • yjs.xxx.edu.cn — 研究生
  • cas.xxx.xxx.edu.cn — 统一身份认证
  • *vpn* / *portal* — 内外网门户
  • *test* / *dev* / *staging* — 测试环境（漏洞密度极高）

六、小程序挖掘专章

6.1 反编译拿源码

步骤 A：拿到 wxapkg 包

方法 1：手机抓包

  • 手机 + Charles / Burp 抓包
  • 进入小程序 → 抓 https://servicewechat.com/... 的请求

方法 2：PC 端文件系统（最稳）

步骤 B：反编译

6.2 反编译后必看的几处

打开源码，Ctrl+Shift+F 全局搜索以下关键词：

关键词 可能找到
http:// / https:// 后端 API 域名
apiKey / secret / token 密钥 / Token
password / pwd 写死的管理员密码
aes / des / md5 / rsa 加密逻辑（可逆可破）
wx.login / getUserInfo 微信鉴权逻辑
appid / AppSecret 公众号配置
Bypass / debug / test 测试逻辑、未发布功能
localStorage / setStorageSync 本地存储的敏感数据

重点：很多小程序把管理后台、运营 API、H5 站点也写在前端，找到就能直接访问。

6.3 抓包 + 业务漏洞挖掘

配置 Burp / Charles 抓包

  1. 手机 / 模拟器配代理
  2. 安装 CA 证书（抓 HTTPS）
  3. 进入小程序，操作核心功能（登录、查询、支付）

重点抓的接口

  • 登录接口（/login、/auth）— 看加密逻辑能不能复现
  • 用户信息接口（/user/info、/profile）— 改 uid 越权
  • 列表 / 详情接口（/list、/detail）— 翻页 / 越权
  • 支付 / 订单接口 — 改金额、并发、重放
  • 上传接口 — 文件类型绕过、路径穿越
  • 后台管理接口（如果前端代码里有路径）— 测未授权

抓包辅助技巧

6.4 小程序高频漏洞 TOP 5

  1. 前端硬编码密钥 / API 域名 → 直接打后端
  2. 鉴权只看客户端标志（如 isAdmin=true）→ 改包越权
  3. 登录态可复用 / Token 不过期 → 抓包能复用很久
  4. 业务接口水平越权（改 userId 看别人的数据）
  5. H5 跳转未过滤（小程序里嵌的 H5 可能直接打）

  • 选 1 所目标高校，跑完子域 + 端口 + 目录

  • 主攻备份文件 / 目录遍历

十、几个重要提醒

  1. 不要越界：未授权访问拿到数据后，不要下载、不要传播、不要进一步渗透，截图证据就够了
  2. 不要 DoS：别跑大流量扫描、别跑并发攻击
  3. 不要上传真实 WebShell：文件上传漏洞只验证能不能上传，不放真实木马
  4. 遵守 SRC 规则：每个平台都有”测试范围”和”禁止行为”，先看规则再动手
  5. 保留完整证据：从发现到复现全流程录屏 / 截图，报告时一目了然
  6. 耐心：第一单可能 1-2 周才出，正常。edu 站水虽低但也有人在挖，需要找到别人没看到的角度
